### 2026-11-21 — M10 PHP backend, M11 live features, M12 hardening
- **One logic, two runtimes.** The PHP API stores the same JSON documents as the browser's local adapter (`rows(tbl, id, data)` in SQLite, WAL, busy_timeout 3000) plus relational tables for the op-log, sessions, sign-in links, rate limits, uploads, change polling, presence, signals and the audit log. Each `api/src/routes/*.php` is a line-for-line port of one `packages/data/src/local/routes*.ts` (conventions in `api/PORTING.md`). This replaces the handoff §8 table-per-entity schema: it keeps the ports faithful and the tables map 1:1 to document "tables". Money stays integer cents; times stay UTC ISO strings so string order is time order.
- **HTTP edge.** JSON-only writes (forms from other sites can't send JSON without a preflight) plus a same-origin check guard against CSRF; session cookies are HttpOnly + SameSite=Lax (Secure on https); 240 writes/min per IP; sign-in links are 32-byte, single-use, 15-minute; passwords optional (≥10 chars). Errors carry the same messages the preview shows.
- **Polling instead of WebSockets.** `changes?since=` (a version counter + touched tables) every 4 s while visible, 15 s hidden; ops every 1.5 s; presence heartbeat 5 s (TTL 30 s, pruned on read); signalling every 1 s (60 s retention). No media goes through PHP.
- **Install + owner.** The install wizard writes `data/config.php` (owner, site address, time zone, a 32-byte key). Provider keys are sealed with libsodium secretbox using that key; only the last 4 characters ever leave the server. The owner console lists organisations (one per host), with the branding toggle, paid-until, note, ending-soon and asked-by-email flags, a change log, requests from the landing form, and backups. Branding is active until paid-until + 14 days; hosts set up their brand while it's off and publish once it's on. Brand colours are the four Figma brand modes (Loft, Sunrise, Northwind, Aurelian), not free colour pickers, so contrast stays AA.
- **Production layout.** `loft-prod.zip` puts the landing in `public_html/loft`, the app (HTTP adapter, hash routing so links never need server rewrites beyond agent links) in `public_html/spaces`, the API front controller in `public_html/spaces/api`, and the code + `data/` in `loft-app/` outside the web root. Releases get the zip attached by `release-zip.yml`; `deploy-ftp.yml` runs only if the owner adds FTP secrets. PHP tests run in CI on PHP 8.2 (`php.yml`); this machine has no PHP, so the whole API is verified there.
- **Calls (M11).** A WebRTC mesh for audio (≤6 talking; the lower tab id makes each offer, so no glare), stage mode (host as hub, raised hands, 60 s turns, force-mute without a turn), screen share on its own connections (≤6 viewers, a 1280 px WebP still every 3 s for viewers whose ICE fails — through `/signal` in the preview, uploaded to `rooms/:id/still` on the server), annotations synced as normalised strokes (cleared 10 s after a share ends unless kept), snapshot-to-board (frame + strokes → a new board page), open together (a prompt, never proxied or embedded; the host sees who opened it) and follow-me (the host's viewport, throttled to 4/s). Default STUN is Google's public server, changeable in Admin.
- **SFU/video tiers.** Admin stores the org's own Cloudflare Realtime / Daily / Jitsi keys (sealed) and enforces the daily budget cap logic (pool/day, 80% → 100% → own link, 10-minute grace, never cut a live session). Routing media through an SFU isn't wired in this build: it can't be verified without real provider accounts. Rooms use P2P/stage and offer the host's own link beyond 12. See Open questions.
- **Code splitting.** After the M11 deploy the Lighthouse gate measured the app at 94 on mobile (95 is the bar). Heavy screens are now `React.lazy` chunks with a Suspense boundary inside the shell, so the rail stays while a screen loads. The initial JS is 452 KB instead of 805 KB.
- **Lockfiles.** `legacy/*/package-lock.json` came in with the imported history (M0). The legacy folders aren't workspaces, so npm never installs them: there is one active lockfile (the root) and one `node_modules` (about 190 MB). They stay as part of the record.
- **One branch, three tags.** M10–M12 were built together on `wip/m10` (the PHP port, calls and hardening share the HTTP edge), merged into `main` once, then tagged v0.10.0, v0.11.0 and v1.0.0 on successive docs commits. Their `/m10/`, `/m11/` and `/m12/` snapshots therefore run the same app; the release notes say what each milestone added.
- **Hardening (M12).** `scripts/load-room.mjs` runs in CI against PHP's built-in server: 12 seated + 1 waiting, the seat passing on when someone leaves, 60 concurrent ops from 12 people with gapless seqs, presence for 13, and 429s (never 5xx) under a burst. Owner backups use `VACUUM INTO` for a consistent copy while Loft runs. A contrast test checks 13 text/background pairs in all four brand modes (it caught Aurelian's muted text at 4.10:1; now 4.67:1). The board gained Tab/Shift+Tab to step through objects, arrow-key panning and +/− zoom. Inputs that hide their own outline (search, chat, find) show the focus ring on their container. The second main-loop e2e starts from the calendar: it schedules a session for later today in the browser's time zone (as the preview does; the server uses the host's), attaches a plan, teaches in the room and bills it.

### 2026-11-21 — M9 agents
- **Protocol lives in the data layer.** The agent-link endpoints (`a/<token>`, `/next.json`, `/claim`, `/context/<id>`, `/drafts`, `/report`, `/ask`, `/changes`) are routes in the local adapter with the same rules the PHP server will enforce (seats, approval, revocation, 60/min token bucket, expiry, pause, ≤500 ops, ≤2 agents per room, redaction). Errors come back as `{error, status}`. `docs/agent-link.md` is the spec.
- **Seats** are keyed by runtime + name (User-Agent + `X-Agent-Name`). Workspace links need the host's approval for new seats; space and room links approve on first contact (build rules). Revoking puts the seat's working tasks back in the queue.
- **Drafts.** Every agent write is a draft row. Board drafts are op batches flagged `draft` and authored `agent:<name>`; hosts see them merged onto the board as a dashed layer with "draft by <agent>" on sections, an activity panel, "Review N drafts" and "Pause agents". Accept re-issues the ops into the room's op-log as the host without the flag; plans attach to the session (as an "AI draft" plan), posts go to the stream, checks arrive as check drafts, invoice drafts run Money's draft builder (never sends). Reject deletes with a reason the agent reads in `next.md`; "Ask for changes" re-queues the task with the note as feedback.
- **Board drafts need a room.** A task tied to a session uses the session's prepared room (created on first use), so the draft layer appears where the session will happen.
- **Agent time** comes from `report.minutes` per seat (Agents page, this week) and per task; it is never billed.
- **Links on Pages.** The preview has no server, so the displayed link uses the production form (`tanziro.com/spaces/a/<token>`) with a note that real agents connect once the PHP server is installed (M10). "Run the demo agent" drives the same endpoints from the browser with a scripted agent (`claude (demo)` on the space link), with pauses so the flow is visible.
- **Live sessions.** Drafts are always on the draft layer, so "Let agents edit during live sessions" is stored on the link now and enforced for direct live edits when live features arrive (M11).
- **Copy without pronouns** again: "codex · building the board", "moved on to the next task".

### 2026-11-21 — M8 insights, checks, states
- **Who Insights covers.** Members and payers of the host's non-team spaces (learners and clients). Co-hosts and team spaces (colleagues) are left out. Last seen updates on any request (throttled to 5 min); a new "login" is a visit that starts after 30 min away. "In a room" = presence status busy or an open attendance event.
- **At-risk rule** (any of): not seen for 7+ days, missed 2+ sessions in a row, attendance under 75% over 3+ sessions, under half of due work on time (2+ due), or an overdue fee. Reasons are shown, never a score. Attendance counts attended / (attended + absent + no-show + late cancel); excused is left out. Deltas compare with the previous window of the same length.
- **Automatic nudges** run once a day on the first request (no cron), each once per person per thing: deadline (24 h before a task is due, to those who haven't handed in), missed 2 in a row (to the payer, else the member), fee overdue + 3 days (skipped when Money's +3 reminder already went), and "hasn't opened shared files" after 3 days (off by default; opens are recorded when a member opens a file). **Custom nudges** go to an audience (who hasn't handed in a task, at risk, not seen 7 days, a whole space, or one person) now or at a time; scheduled ones are delivered by the first request after that time. In-app is real; email is simulated on Pages; WhatsApp returns wa.me links the host taps; Push is shown as "soon" (needs the installed app). "This week" stats: sent, opened (notification read) and acted on (a hand-in or payment/claim after the nudge).
- **Quick checks** port the legacy quiz rules: four question types (one answer, several answers, true/false, short answer), objective answers auto-graded, short answers matched case- and space-insensitively against accepted answers or queued for the host to mark (partial marks allowed). Window = status + open/close times + time limit; one attempt by default; questions and options shuffle per member with a stable seed. Members never receive the answer key. A published check past its close time reads as Closed; reopening clears the old close time.
- **Integrity signals.** `tinyproctor.js` 1.1.0 (MIT, the owner's own library) is vendored unchanged in `apps/web/src/vendor/tinyproctor/` with its licence and loaded lazily on the take page only. It runs silent with no endpoint (nothing leaves the page) and never touches camera, microphone or screen; the take page says so before Start. Snapshots (score, counts, time away) are saved with the attempt. `integrityReview()` in core turns them into Clean / Review / Flagged with plain reasons ("left the tab ×2", "pasted text"); it never changes a mark.
- **Gradebook** ports the legacy averages: graded checks count their points, missing work counts as zero once due, tasks show Done / Pending / Missing without points. CSV export in the browser.
- **Atomic attempt writes.** Autosave and integrity snapshots used to read and rewrite the whole attempt, so two quick saves could drop an answer. `LocalDb.update()` now does read-modify-write in one IndexedDB transaction, integrity uses `patch`, and the take page queues saves so Submit waits for them.
- **System states (07).** Offline banner in the shell (`navigator.onLine`), "Reconnecting… the board keeps working" in the room while offline, skeletons for loading (existing), errors with a way out (`ErrorState`: what failed, why, Try again + Go to Home; the invoice run's "Couldn't send N invoices" offers Try again and Copy links), and the room-full host view ("12 / 12 · Rahim is waiting · Let in when free").
- **Preview-only "Take it as …"** on a check's results opens a second tab as that member (`?as=` sets the per-tab identity in the local adapter). It does nothing with the PHP adapter.

### 2026-11-21 — M7 money
- **Numbering follows Figma, not legacy.** Legacy tutorloft numbered `${prefix}-${YYYYMM}-0001`; Figma I1/I3 show `LF-0418` with an editable "Next number". Invoices are `LF-` + a 4-digit sequence that continues from the highest number issued or the host's next number, whichever is higher. Receipts reuse the invoice's sequence (`RC-0412`, then `RC-0412-2` for part payments). Editing a sent invoice creates a revision `LF-0412-B`; sending it voids the original and carries over its payments, claims and questions.
- **Who is billed.** Courses and tutoring bill each member (`per: member`); client, workshop and team spaces bill the space once per session (`per: session`, one log row for the client, payer `"*"`). Team spaces default to Free. Payers are users mapped per member in the space's Billing tab; a member with no payer produces a draft in "Needs attention".
- **Pricing.** Per session = the space price; per hour = minutes × rate ÷ 60 rounded half-up to the cent (`prorate`); monthly = one line per member (or per client) per month, even with no sessions; package = sessions draw down an active package (log row shows "Package n/16", amount "credit"). Excused gives $0 and, if the space and rule allow, a makeup credit that the next invoice applies as a negative line. Invoiced rows are frozen; status changes re-price unbilled rows only. Billing changes apply to rows written from then on.
- **No cron.** The first request of the day (`nav`, Money pages) runs the money task: drafts last month's invoices on the first request on/after the 1st (`lastAutoRun`), sends due reminders, expires makeup credits, and drafts package renewals at the threshold. Reminders skip steps that were missed rather than sending a burst.
- **Reminders.** Steps −3, 0, +3, +10 (final) days with per-step channels. In-app is real; email is recorded and sent by the PHP server in M10 (the preview says it is simulated). WhatsApp is never sent: a due WhatsApp step queues a "WhatsApp reminder to send" item in To review, and "Send nudge now" opens a `wa.me` link in the host's own WhatsApp. An open claim pauses reminders; a host can pause a payer. Overdue = past due, balance > 0, no open claim.
- **Pay page.** `/pay/<token>` needs no sign-in (the unguessable token is the key) and shows only that invoice: lines with session dates, the host's payment link, "I've paid" (amount, method, reference, note), questions per line, receipts, and a print view. Views count once per 30 minutes. Loft never sees card or bank details.
- **Payment link.** One default link in Money (same for everyone, a template with `{amount}`/`{ref}`, or per payer), optionally overridden per space. `settings.paymentLink` mirrors the default for older screens.
- **Copy without pronouns.** Figma's "Shirin Karim says she paid" is written as "Shirin Karim says LF-0412 is paid" / "says it's paid" so the app never guesses anyone's pronouns.
- **CSV export** is built in the browser from the log query (same columns the PHP endpoint will return in M10).
- **Seed v6** writes the money demo through the same code paths (`recordAttendance`, `buildDrafts`, `sendInvoice`, `confirmPayment`, `sellPackage`) with times relative to now, so states are stable on any date: LF-0412 "Payer says paid", LF-0413 partly paid and 6 days overdue with a WhatsApp reminder queued, a paid 16-session package, and this month's unbilled rows (including Dipa with no payer). Demo phone numbers are fictional and links point at `pay.example.com`.
- **Fix:** the seeded "Wrap-up pending" lesson used to be the latest Mon/Wed class, so on days when it ended more than 24 h earlier, auto-wrap closed it on first load. It is now a one-off session that ended 2 h ago.

### 2026-11-21 — M6 plans
- **Plans tab** is inserted for hosts in every mode (after Chat); for workshops the existing "Agenda" tab becomes the plans tab, labelled "Agenda".
- **Status rule:** Draft until attached *and* at least 80% of the length is planned, then Ready; Taught after wrap-up. An AI draft keeps the "AI draft" badge until its blocks are edited.
- **Autosave** sends the whole block list after 800 ms of quiet, and every save that changes blocks writes a version (restorable). Attached plans re-prepare on save so pages and the agenda follow edits.
- **Attach & prepare** is idempotent: the session remembers its room, page ids per block, agenda post id and reminder id, and re-attaching updates them. Reminders are stored as scheduled items and delivered by the first request after their time (no cron).
- **Room rail:** state `{current, startedAt, extensions}` lives on the session, so reloads resume. "Start next block" moves the host's board to that block's page. Moving *everyone's* board (follow-me) arrives with M11; members already see "Now / next".
- **Wrap-up** writes `session_log` rows keyed `sessionId:memberId` (re-saving overwrites, never duplicates). Billable statuses default to attended, late cancel and no-show; the price comes from the space's `billing.unitPriceCents` (seeded for the demo; set in Billing setup in M7). Partly/skipped blocks can be carried into the next untaught plan, or a carry tray.
- **Attendance** comes from `rooms/:id/attendance` join/leave events recorded by the room page.
- **Plan from a file** counts PDF pages with pdf.js and creates one Board block per page; page headings need the text layer, so titles are "Page n" for now.

### 2026-11-21 — M5 scheduling
- **Time zones** use only `Intl` (no date library): `zonedToUtc` converts a wall time in a zone to UTC and re-checks the offset so DST transitions land correctly (tested for London and New York). Sessions are stored as UTC ISO strings.
- **Series** are materialised as rows linked by `seriesId` (max 200 per series); moves and cancels ask "this / this and following / all".
- **Free slots** = availability ranges in the host's zone, minus sessions (not cancelled) and busy blocks, each widened by the buffer; then minimum notice, per-day cap and horizon. Steps are 30 minutes.
- **Busy calendar:** the PHP API (M10) fetches the pasted iCal URL at most every 15 minutes. Browsers can't fetch calendar feeds cross-origin, so the Pages preview accepts pasted `.ics` text instead. The parser handles single events and simple weekly RRULEs (BYDAY, COUNT, UNTIL, INTERVAL) and treats TZID times as UTC (busy only, never written back).
- **Calendar feed:** production serves `GET /ics/<token>.ics` (M10). The preview offers a downloadable snapshot of the same feed.
- **Bookings** create a session (`requested` with manual approval, otherwise `scheduled`). The slot is re-validated on submit, and a filled honeypot field returns a fake success. The manage link token needs no login.
- **Requests:** a move on a group session becomes a one-off copy for that member; on a 1:1 space the session itself moves. A member's cancel on a group session is recorded as an attendance exception (used by billing in M7). Pending requests expire at the original start time. The late-change window defaults to 24 h until billing settings (M7) set it per space.
- **Calendar shading** draws the host's weekly hours on the viewer's local grid (the host is the viewer here).

### 2026-11-21 — M4 board v2
- **Rendering layers:** pages and sections (DOM) → highlighter, shapes and connectors (world-space SVG) → shape labels, connector labels, notes and text (DOM, so text wraps and edits natively) → pen ink (SVG, on top) → selection, guides and handles. Live strokes update one SVG path imperatively. (The M2 canvas ink layer was replaced.)
- **Smoothing** stores raw points plus a `smoothing` value per stroke and renders the perfect-freehand outline, so the slider can change later; pressure comes from `PointerEvent.pressure` for pens only.
- **Shape recognition** commits the stroke, then a batch that swaps it for a shape, so one undo restores the stroke. Rectangles, ellipses and diamonds are recognised; triangles are not (the Figma shape set has no triangle).
- **Undo records** are taken against a state ref that each commit advances synchronously, so several commits in one tick (recognition, batches) undo correctly.
- **Connectors** store `{id, anchor}` or `{x, y}` ends and are routed on every render, so they follow moves and resizes for free. Deleting a shape also deletes connectors attached to it.
- **Sections** carry everything fully inside them when moved; marquee selects sections only when they are fully inside the box.
- **Diagram objects** store only code and a position; the layout is recomputed on render. "Detach to freeform" replaces the diagram with ordinary shapes, connectors and lane sections. ERD relations are drawn as labelled connectors (`1 → n`) rather than crow's-foot caps; sequence diagrams use dashed lifelines and horizontal messages.
- **pdf.js** (37 MB as an npm package) is not installed. The app loads the pinned `pdfjs-dist@4.10.38` ESM build on demand from `<base>vendor/pdfjs/` if present, otherwise from jsDelivr. Production can self-host by copying `pdf.min.mjs` and `pdf.worker.min.mjs` there.
- **Google Slides/Docs links:** Google's `/export/pdf` doesn't allow cross-origin fetches from a browser. The import tries, then explains how to download the PDF and drop it in. The optional PHP proxy (M10) can fetch it server-side.
- **PDF export** uses a ~90-line in-house writer (one JPEG per page, DCTDecode, A4 by default) instead of a PDF library.

### 2026-11-21 — M2 rooms + board v1
- **Room codes** follow Figma's "Join with code": 6 characters as `K7P-42Q`, from an alphabet without I/L/O/0/1. `normaliseCode` accepts lowercase, spaces or a full `…/r/<code>` link.
- **Board engine** (`packages/board`) is framework-free: object model, op-log reducer (ops applied in `seq` order = last-writer-wins per field; an update can't change an object's kind), geometry, RDP simplification + quantisation of strokes, and a per-user undo stack built from inverse ops. Ops carry a client `_cid` so the view can apply them optimistically and drop them when the echo arrives.
- **Layers:** dot grid (CSS, scaled with the view) → pages (DOM sheets) → notes/text (DOM) → ink (canvas, pointer-events off) → cursors. Ink sits on top so people can write over pages and notes.
- **Eraser** removes whole strokes it touches (object eraser) instead of the legacy pixel eraser: pixel erasing can't be expressed as op-log edits.
- **Text lock:** while someone edits a note, their presence carries `editing: <id>` and others see a lock with their name instead of an editor (no CRDT).
- **Capacity on Pages** is decided from presence: humans with `status: "in"` (agents never count). Newcomers wait 0.6 s for presence to settle, then take a seat or join the line ordered by `joinedAt`; a freed seat admits the head of the line. The host is always seated. Covered by a 13-tab Playwright test.
- **Guests in the preview:** IndexedDB is shared per browser, so `/join` creates a guest user for the tab (`setTabIdentity`). Opening `/r/<code>` directly in the same browser is the host. The share popover links to `#/join?code=…&as=guest` to demo two people.
- **Share popover:** the design's QR button is replaced by the room code chip for now (no QR encoder dependency yet); WhatsApp and Email links work.
- **Session ended** offers "Download the board (PNG)" today; PDF export arrives with M4.
- **Wording:** toasts and buttons avoid gendered pronouns ("Let them speak"), unlike one Figma sample.

### 2026-11-21 — M0 scaffold and pipeline
- **Toolchain versions:** Vite 7, React 18.3, TypeScript 6.0 (typescript-eslint supports < 6.1), ESLint 9, Vitest 5, Playwright 1.65. Vite 8 / TS 7 were skipped until the lint tooling supports them.
- **One root tsconfig** (`tsc -p tsconfig.json`, `noEmit`) instead of project references: fewer files, same strictness.
- **Tokens:** values copied once from the Figma variables into `packages/ui/tokens.json`; `npm run tokens` writes `tokens.css`, and `npm run check` fails when the CSS is stale. Modes are `[data-theme="loft|sunrise|northwind|aurelian"]`.
- **Conflict (Figma vs handoff):** the Figma variable `brand/domain` holds custom domains (e.g. `learn.sunriseacademy.edu.bd`). The handoff forbids custom domains, so that variable is **not** exported; branded orgs live at `tanziro.com/spaces/<org-slug>`.
- **Fonts:** latin-subset woff2 from Google Fonts (SIL OFL 1.1), self-hosted in `packages/ui/fonts` (≈148 KB total). Upright only.
- **Routing on Pages:** GitHub Pages serves a single root `404.html` for the whole site, so per-snapshot `404.html` copies cannot work for `/m<N>/app/`. Pages builds use `HashRouter` (`VITE_ROUTER=hash`); production uses `BrowserRouter` with `.htaccess`.
